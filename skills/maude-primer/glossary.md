# Maude 2.0 Primer — Glossary

**ad-hoc overloading** — same operator name at unrelated ranks; disambiguate constants via `(A).Letter`, `(A).Note` (Ch 2)
**assoc** — binary-operator attribute declaring grouping irrelevant (Ch 1)
**Bool** — provided sort: `true`, `false`, `==`, `=/=`, `and`, `or`, `if_then_else_fi`; comparisons (`<`, `<=`, ...) are NOT provided (Ch 2)
**canonical form** — the constructor-only term an expression must reduce to (Ch 2)
**class** — declaration giving objects a schema: `class TABLE | occupied : Bool , chairs : Nat .` (Ch 4)
**cmb** — conditional membership axiom keyword (Ch 2)
**comm** — attribute declaring argument order irrelevant (Ch 1)
**Condition** — meta-level sort for rule/equation conditions; same forms as level-0 (Ch 6)
**configuration** — the multiset of objects and messages omod rules match against (Ch 4)
**connected component** — the graph of sorts linked by `subsort` declarations; one kind per component (Ch 1)
**confusion** — adding equations that redefine imported terms' reduction behavior (Ch 2)
**constructor [ctor]** — fundamental operation generating a sort's values; constructor terms are irreducible by definition (Ch 1)
**Context** — Result4Tuple's fourth element: the untouched surroundings of an extended rewrite, hole written `[]` (Ch 6)
**Core Maude** — the base interpreter level: `fmod`/`mod`; everything Core is also in Full Maude (Ch 1)
**descent functions** — metaReduce, metaRewrite, metaApply, metaXapply, metaFrewrite, metaSearch — execute modules-as-data (Ch 6)
**encapsulation** — grouping data under one name, exclusive of everything else; the object's "temple of memory" idea (Ch 4)
**equation (eq)** — simplification rule; convention demands the RHS be strictly simpler (Ch 2)
**error term** — a mis-typed application inside a connected component; lives in a kind rather than a sort (Ch 1)
**extending** — importation mode: junk allowed, confusion forbidden (Ch 2)
**failure result** — `(failure).ResultTriple?` / `(failure).Result4Tuple?`: no-match results, the meta-loop terminator (Ch 6)
**fmod / mod / omod** — functional / system / object-oriented module delimiters (`endfm`/`endm`/`endom`) (Ch 1)
**fth** — functional theory declaration (Ch 5)
**Full Maude** — Core Maude extended by an interpreter written in Maude via LOOP-MODE; all input parenthesized (Ch 4)
**gather (e E &)** — per-argument precedence constraints: `e` strictly-lower prec, `E` lower-or-equal, `&` anything; default `(& &)` (Ch 2)
**identity (id: e)** — two-sided identity attribute on binary operators; also `left id:`, `right id:` (Ch 1)
**including** — importation mode allowing both junk and confusion (Ch 2)
**instantiation** — plugging views into a parameterized module: `( select NETWORK(Graph-GreekGraph) . )` or `pr M(V)` (Ch 5)
**internal strategy** — a meta-programmed order of rule application (rewriteExcept, SANS, CIGARETTE-TEST patterns) (Ch 6)
**iter** — unary-operator attribute enabling `s_^5(0)` iteration notation (Ch 1)
**junk** — new ground terms added to an imported sort's carriers (Ch 2)
**kind ([Sort])** — automatic supersort of a connected component, holding its error terms; equations with kind-level variables reduce error terms too (Ch 1, 2)
**label ('qid)** — statement attribute naming rules/equations/membership axioms for meta-level targeting (Ch 6)
**LOOP-MODE** — standard module with `op [_,_,_] : QidList State QidList -> System`; the REPL engine under Full Maude (Ch 4)
**matching condition (:=)** — condition form matching pattern against term; also reads as value assignment (Ch 2)
**mb** — membership axiom keyword (Ch 2)
**membership axiom** — statement refining sort classification (`t : S`), of which op and subsort declarations are syntactic sugar (Ch 2)
**memo** — operator attribute caching reductions of expressions with that top operator (Ch 2)
**message (msg / Msg)** — `msg name : Oid ... -> Msg`; a note beside its addressee object (Ch 4)
**metadata "..."** — statement attribute readable by meta-programs (Ch 6)
**META-LEVEL** — standard library module defining Term, Module, Substitution, descent functions; imports META-TERM and META-MODULE (Ch 6)
**metaApply / metaXapply** — single named-rule application; metaXapply rewrites with extension and returns a Context (Ch 6)
**mixfix** — operator form using underscores as argument places: `op _+_`, called `s(0) + s(0)` (Ch 1)
**module** — "the key concept of Maude": a set of definitions forming an algebra (Ch 1)
**Oid** — built-in sort of object identifiers; may be computed constructor terms (Ch 4)
**oth / endoth** — object-oriented theory delimiters (Ch 7)
**owise** — statement attribute: fires only when sibling statements did not match (Ch 2)
**parameterized module** — frame module `(fmod M(X :: T) is ... endfm)`; frame sorts `S(X)`, theory sorts `X@S` (Ch 5)
**prec** — operator precedence attribute; default 41; LOWER number binds tighter (Ch 2)
**prefix** — operator form `+(X, Y)` (Ch 1)
**protecting** — importation mode forbidding junk and confusion (Ch 1)
**Qid / QidList** — quoted identifiers `'word`; the I/O vocabulary of LOOP-MODE (Ch 1, 4)
**ResultPair / ResultTriple / Result4Tuple** — `{Term, Type}` / `{Term, Type, Substitution}` / plus Context (Ch 6)
**rewrite law (rl / crl)** — labeled, irreversible transition `rl [name] : A => B .` between same-sort states (Ch 3)
**rew / frew / continue** — rewrite with default strategy / fair strategy / extend previous run by n steps (Ch 3)
**search (=>+ / =>!)** — reachability query: at-least-one-step target / terminal (irreducible) target (Ch 3)
**select** — set the current module; `red in MOD : e` scopes one reduction (Ch 2)
**singleton** — the sub-sort trick making single elements valid lists (Ch 1)
**sort** — a category for values; declared `sort` / `sorts` (Ch 1)
**State** — the all-encompassing sort rewrite laws transition within; more specific states are subsorts (Ch 3)
**statement** — any op/eq/mb/subsort/rl declaration; all end with a period (Ch 1)
**strategy** — an order of rule application; `rew` and `frew` are built-in defaults (Ch 3)
**subsort** — "qualifies as a" relation: `subsort NzNat < Nat .` (Ch 1)
**subsort overloading** — redefining an operator at subsorts with a refined result; attributes must match (Ch 2)
**Substitution** — set of `X <- T` assignments (`none`, `;`-glued) pinning rule variables in metaApply (Ch 6)
**syntactic sugar** — friendly keywords (op, vars-dots) for what membership logic could say directly (Ch 2)
**system module (mod)** — module containing equations plus rewrite laws (Ch 3)
**Term / TermList** — meta-represented expressions: `'c.Sort` constants, `'X:Sort` variables, `'op[...]` applications (Ch 6)
**theory** — uninterpreted contract a parameter must satisfy (fth; oth for omods) (Ch 5)
**TRIV** — built-in theory requiring only "a sort Elt" (Ch 5)
**up / down** — reflection-level shifters: expression to metaterm and back (Ch 6)
**variable** — sorted placeholder (var/vars); never assigned or carried between operations (Ch 1)
**view** — theory-to-parameter binding map (`sort ... to ...`, `op ... to ...`, `op f to term ...`) (Ch 5)
